# Therapists — Current State

## Implemented (DB level)

`public.therapists`: `id`, `name`, `archived`/`archived_at`/`archived_by`/
`archived_reason` (soft-archive pattern, not hard delete).

Availability/scheduling support tables:
- `therapist_absence` (one-off dated absences)
- `therapist_leave` (date-range leave, `end_date >= start_date` checked)
- `therapist_day_off` (recurring weekday off, `weekday` 0–6 checked)
- `therapist_services` (join table: which services a therapist can perform)

## Implemented (app level)

- `app/dashboard/page.tsx` reads a live count of `therapists` where `archived = false` ("Available Therapists" card).
- `app/(staff)/therapists/page.tsx` (`TherapistBrowser` component,
  `components/therapist-browser.tsx`) implements the full HTML mockup
  parity:
  - Default 10 therapists matching mockup (`Ron`, `Don`, `Tristan`, `Leo`, `Roy`, `Xander`, `Dan`, `Marco`, `Akio`, `Josh`) — only used as a fallback if the live `therapists` table is empty; all 10 exist live.
  - Interactive Date (defaults to the device's real local date, via a local-time `todayISO()` — not `toISOString()`, which is UTC and drifts a day off near local midnight), Time (`16:00` to `01:00`), and Availability filters (`Select All`, `Available`, `Booked`), plus `Show Archived` toggle.
  - **Weekly Day(s) Off toggle pills (`Sun`–`Sat`) — real Supabase persistence** (`ohm#7k2m9x4p`, 2026-08-30): writes through `app/(staff)/therapists/actions.ts` (`toggleDayOff`) to `therapist_day_off`, keyed by real therapist `id` (component holds a `therapistIds`: name→id map alongside the existing name-keyed `therapistMeta`, updated on rename). Page-level fetch now selects `therapists.id` (not just `name`) and joins `therapist_day_off` to seed initial state. RLS: `staff_select`/`staff_insert`/`staff_delete` on `therapist_day_off` (`is_staff()` read, `is_supervisor_or_above()` write) — see RLS section below, this table had **no policies at all** before this fix. Services Offered toggle pills (`Combi Massage`, `Signature Massage`, `Scrub`) remain **local-state only**, not persisted — out of this fix's scope, unchanged.
  - Kebab dropdown menu on each therapist card supporting `Mark Absent Today`, `Mark On Leave`, `Archive`, `Unarchive`, and `Edit` (rename) — **fixed** (`ohm#7k2m9x4p`, 2026-08-30): the menu's actions themselves were already correctly wired, but a `document`-level click-outside-to-close listener closed the menu in the same tick it opened, because it and React's own delegated click listener are both attached to `document` in this React/Next version — a sibling listener on the same node isn't stopped by `e.stopPropagation()`. Fixed by having the close listener explicitly skip clicks that land inside a `data-kebab-root`-marked wrapper instead of relying on `stopPropagation()`. At the time, `Archive`/`Unarchive`/`Edit` (plus Add Therapist) were all local-state only — see below for what's since changed.
  - **`Mark Absent Today` / `Mark On Leave` — real Supabase persistence + Dashboard reassignment trigger** (`ohm#3f8q1w6z`, 2026-08-30): `handleMarkAbsent`/`handleConfirmLeave` now call new server actions `markAbsentToday()`/`markOnLeave()` (`app/(staff)/therapists/actions.ts`) instead of only mutating local state. `markAbsentToday` upserts `therapist_absence` (ignoring the unique `(therapist_id, absent_date)` conflict if already marked) then flags that therapist's same-day `Booked` bookings to `Needs Reassignment`; `markOnLeave` inserts `therapist_leave` then flags `Booked` bookings across the leave's date range the same way. Both log one `action_logs` row and revalidate `/therapists` + `/dashboard`. `app/(staff)/therapists/page.tsx` now also fetches `therapist_absence`/`therapist_leave` and seeds `TherapistBrowser`'s `initialAbsence`/`initialLeave` props (previously always empty on load — a page refresh silently lost the "who's absent/on leave" state even before this fix, since nothing was ever persisted). Flagged bookings then surface on `/dashboard` with a Transfer action — see [[dashboard_state]].
  - **`Archive` / `Unarchive` — real Supabase persistence** (`ohm#7m2w9dxk`, 2026-09-01): `handleConfirmArchive`/`handleUnarchive` now call new server actions `archiveTherapist()`/`unarchiveTherapist()` (`app/(staff)/therapists/actions.ts`) instead of only mutating local state. `archiveTherapist` updates `therapists.archived`/`archived_reason`/`archived_by`/`archived_at`, then flags that therapist's `Booked` bookings to `Needs Reassignment` — same UPDATE shape as `markAbsentToday`, deliberately with **no date filter** (archive is permanent, unlike a one-day absence or a bounded leave range), matching the pre-existing local-only behavior this replaces. `unarchiveTherapist` clears those four columns; it does not un-flag any booking (unmarking a `Needs Reassignment` row isn't built anywhere in this codebase — append-only for this phase, same as absence/leave). Neither action touches `therapist_day_off` or `therapist_services` — a therapist's day-off/services rows are left exactly as they are through an archive/unarchive cycle. `app/(staff)/therapists/page.tsx` now also fetches `therapists.archived`/`archived_reason`/`archived_at` and seeds `TherapistBrowser`'s new `initialArchived` prop (previously the component always initialized every therapist as `archived: false` regardless of live DB state — a page refresh would have silently un-archived everyone in the UI even before this fix, since nothing was ever persisted). **`Edit` (rename) and Add Therapist are still local-state only / broken** — see the note below and RLS section.
  - Add Therapist modal, Daily Schedule modal, Mark On Leave modal, Archive modal, and Edit Name modal with toast feedback. Daily Schedule and Edit Name modals remain local-state only, unchanged. **Add Therapist is not actually local-state only** — `handleConfirmAdd` already calls a real server action (`createTherapist()`) that inserts into `therapists`; the docs previously mis-described this as a cosmetic local stub. It's actually **silently RLS-rejected**: the table has no INSERT policy, so the insert fails and the UI shows an error toast rather than adding the therapist, local or otherwise. This is a bug (not a scoping gap) — fix is a follow-up prompt (INSERT policy on `therapists`, same as this prompt's UPDATE policy).
  - **Copy Available-List to clipboard** (`ohm#9d4r7t2h`, 2026-08-30): a copy-icon button next to "Show Archived" runs `handleCopyAvailable`, which filters the existing `cardRows` (already computed per-card `slotStatus`, respecting day-off/leave/absence/archive/busy logic — no new filtering added) for `slotStatus === "available"`, and copies `"{fmtTime(viewTime)} Available\n\n{Name}\n..."` to the clipboard via `navigator.clipboard.writeText`, confirmed with the existing toast. Client-only, no persistence, no backend involvement.
